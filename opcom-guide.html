● Home Assistant integration

OPCOM Romania prices, made simple.

See tomorrow's electricity prices today, and let your battery, EV or heat pump run when power is cheap. This guide takes you from install to your first automation — no technical background needed.

What it actually does

OPCOM is Romania's power market. Every day around 2 pm it publishes the electricity prices for the next day, in 15-minute slices. This integration reads those prices and brings them into Home Assistant.

You get the price right now, the cheapest and most expensive hours of the day, and simple on/off signals you can plug into automations — like «should charge now» that turns on only during the cheapest blocks you chose.

No accounts, no license keys, nothing to pay. It reads a public page on opcom.ro.

Before you start

You need Home Assistant up and running, with HACS installed (HACS is the «app store» for Home Assistant add-ons). If you don't have HACS yet, follow hacs.xyz first — it's a one-time setup.

Install it

Pick the way that matches how you received it.

  1. Copy the link

    Get the GitHub link from whoever shared it with you (something like github.com/…/opcom_ro).

  2. Add it to HACS

    Open Home Assistant → HACS → the three dots (top right) → Custom repositories. Paste the link, set Category to Integration, click Add.

  3. Install

    Back in HACS, search OPCOM Romania, open it, click Download.

  4. Restart Home Assistant

    Settings → System → top-right menu → Restart Home Assistant. Wait for it to come back.

  5. Add the integration

    Settings → Devices & Services → Add integration → search OPCOM Romania → click it.

  1. Unzip what you received

    You should have a folder named opcom_ro. (If it's a .zip, extract it first.)

  2. Open your config folder

    Find your Home Assistant config folder — the same place your configuration.yaml lives. Inside it there should be a custom_components folder; if not, create one.

  3. Copy the folder in

    Put the opcom_ro folder inside custom_components. So the path looks like custom_components/opcom_ro/.

  4. Restart Home Assistant

    Settings → System → top-right menu → Restart Home Assistant.

  5. Add the integration

    Settings → Devices & Services → Add integration → search OPCOM Romania → click it.

Set it up

When you add the integration, a form appears. Here's what each option means in plain language:

Currency

RON = prices in lei/MWh (from the Romanian page). EUR = prices in euro/MWh. Pick what you think in.

Resolutions

How fine-grained the data is: 15 / 30 / 60 min. For battery automations, 15 min is best. For a quick glance, 60 min is enough. You can pick more than one — each creates its own set of sensors.

Refresh interval

How often to re-check OPCOM. 5 min is a good default. Prices only change once a day, but this keeps the «current price» fresh.

Window duration & number of windows

This is the smart part. «Find the 3 cheapest blocks of 60 min» means it scans the whole day and picks the three cheapest non-overlapping hours — those become your «charge now» windows.

Low / high price threshold optional

Extra guard rails. For example, only allow charging when price is also below 600 lei. Leave at 0 to ignore.

Cheap / expensive percentile

Another way to gate: «cheap» = the cheapest 25% of the day, «expensive» = the top 25%. You can change the percentages.

You can change any of this later: Devices & Services → OPCOM Romania → Configure.

What you get

After setup, a device named OPCOM Romania appears (one per resolution). Under it:

Price sensors

Price now

The price of the current slice. Tap it to see the whole day's curve as a list.

Next price

What the price becomes in the next slice — handy to see a jump coming.

Average today / tomorrow

The day's average price, plus OPCOM's Base/Peak/Off-Peak figures.

Cheapest window today charge

The best block to consume. Its details list all the windows it found.

Most expensive window today discharge

The best block to export/sell back to the grid.

Cheapest / most expensive tomorrow

Same, for tomorrow — appears after OPCOM publishes (~2 pm).

Current price percentile

Where today's price sits: 0% = cheapest moment, 100% = priciest.

On/off signals (for automations)

Should charge now ON = cheap

Turns on when you're inside one of the cheapest windows (and below your threshold, if set). This is the one you wire to your battery/EV.

Should discharge now ON = pricey

Turns on during the most expensive windows — export/sell power.

Price below / above threshold

Simple on/off by a fixed price. Only appears if you set a threshold.

Cheap / expensive (percentile)

On when the current price is in the cheapest or priciest slice of the day.

Make it do something

Here's the payoff: turn things on only when power is cheap. Create these under Settings → Automations → Create automation → Edit in YAML.

Charge a battery when power is cheap

# Start charging when the cheap window opens
alias: Battery charge on cheap power
triggers:
  - trigger: state
    entity_id: binary_sensor.opcom_romania_15_min_should_charge_now
    to: "on"
actions:
  - action: switch.turn_on
    target:
      entity_id: switch.battery_charge

# And stop when the window closes
alias: Battery stop charging
triggers:
  - trigger: state
    entity_id: binary_sensor.opcom_romania_15_min_should_charge_now
    to: "off"
actions:
  - action: switch.turn_off
    target:
      entity_id: switch.battery_charge

Show the price curve on your dashboard

If you use the ApexCharts card, add this to a dashboard card:

type: custom:apexcharts-card
header:
  show: true
  title: OPCOM prices today
series:
  - entity: sensor.opcom_romania_15_min_current_price
    attribute: prices
    type: column

A note on entity names

The exact names end with the resolution you picked (here _15_min). If you chose 60 min, it'll be _60_min. Find yours under Devices & Services → OPCOM Romania → the device → entities.

Something went wrong?

If a price is missing or a sensor stays unavailable, you can send a file to whoever helps you with this integration. There are two ways — start with the first.

Quick — the diagnostics file one click

This is a snapshot of what the integration currently sees. It's a small JSON file with no personal data.

  1. Open the integration

    Settings → Devices & Services → click OPCOM Romania.

  2. Download diagnostics

    Click the three dots ⋮ top-right of the entry card → Download diagnostics. A .json file downloads.

  3. Send it

    Attach that file in your message. It contains your settings, whether the last update worked, and a summary of today's/tomorrow's prices.

Deeper — the debug log file for intermittent issues

If the problem comes and goes, turn on the debug log so every fetch is recorded to a file you can share.

  1. Turn on the debug log

    Devices & Services → OPCOM Romania → Configure → switch on Enable debug log file → save. The integration reloads.

  2. Start fresh

    Find the OPCOM Romania device → press the Clear debug log button. This empties the log so it only contains your next attempt.

  3. Reproduce the issue

    Use the integration as normal, or press Refresh now to force an immediate fetch. Wait a minute or two.

  4. Grab the file

    The log is at opcom_ro_debug.log in your Home Assistant config folder (the folder with configuration.yaml). Open it with the File editor add-on, or copy it out via Samba/SSH, and send it.

  5. Turn it off when done

    Go back to Configure and switch Enable debug log file off so it stops writing.

What's in the log?

Only fetch events: which day it asked for, whether it succeeded, how many prices came back, and any error text. No personal data, no secrets — prices are public.

Good to know

Tomorrow's prices are missing / say «unavailable»

Normal. OPCOM publishes next-day prices between ~1 pm and 3 pm Romania time. Before that, tomorrow's sensors are unavailable. They'll fill in by mid-afternoon.

Are the prices in lei or euro?

Whichever you picked at setup. RON = lei/MWh (Romanian source). EUR = euro/MWh (English source). Both come straight from OPCOM.

What timezone does it use?

Romania's (Europe/Bucharest). So «current price» always matches the Romanian delivery day, even if your Home Assistant runs in another timezone.

«Should charge» and «should discharge» are both on at once

You've covered too many hours. If «window duration × number of windows» gets close to 24 h, the cheap and expensive blocks start overlapping. Reduce the number of windows or the window length.

Can I change settings later?

Yes. Settings → Devices & Services → OPCOM Romania → Configure. Changing options reloads the integration automatically.
